# Контракт данных: AI Avitolog → дашборд

Договорённость между двумя проектами о новых блоках дашборда: касса, чаты,
состав инвентаря, партии ставок, план/факт.

- **Писатель** — проект `C:\Projects\AI Avitolog` (сессия стратега). У него
  ключи API Авито и вся логика расчётов. Каждое утро кладёт в базу дашборда
  готовые строки.
- **Читатель** — этот проект (`C:\Projects\stats2`). Заводит таблицы, читает
  их и рисует. Ключей API не получает, расчётов не повторяет.

Существующий поток (`daily_stats` через `import_folder.py`) не меняется.

## Правила для обеих сторон

1. **Таблицы заводит читатель** — в `avito/db.py`, рядом с `daily_stats`,
   чтобы `metadata.create_all` создал их при старте. Писатель таблиц не
   создаёт и схему не меняет.
2. **Писатель пишет только в таблицы этого файла.** `daily_stats`,
   `accounts`, `calls` он напрямую не трогает.
3. **Запись идемпотентна**: `INSERT ... ON CONFLICT (первичный ключ) DO UPDATE`.
   Один и тот же день можно записывать сколько угодно раз. Каждое утро
   переписываются вчера и позавчера.
4. **Аккаунт — полный id кабинета Авито строкой** (`avito_id`, например
   `419821780`). Имя для показа читатель берёт из `accounts.avito_id`.
   Внешнего ключа на `accounts.id` нет: писатель не знает внутренних номеров.
5. **Нет строки — нет данных, а не ноль.** История доливается на разную
   глубину; пропуск рисуется разрывом, не нулём. То же для `NULL` в колонке.
6. **Деньги — в рублях** (`Float`, как в `daily_stats`). **Время — МСК.**
   Сутки режутся по московской полуночи.
7. **Только агрегаты.** Текстов переписки, телефонов и имён учеников в этих
   таблицах нет и не будет.
8. **Изменения схемы — сначала правкой этого файла.** Новые колонки
   добавляются только как `NULL`-допустимые, существующие не
   переименовываются.
9. В каждой таблице есть `loaded_at` (`DateTime`, UTC) — когда строка
   записана. По нему видно свежесть данных.

## Таблицы

### `kassa_daily` — деньги дня

Одна строка на день и аккаунт. Ключ: (`stat_date`, `avito_id`).

| колонка | тип | смысл |
|---|---|---|
| `stat_date` | Date, PK | день (МСК) |
| `avito_id` | String(40), PK | кабинет |
| `deposits_rub` | Float | внесено за день минус возвраты |
| `deposits_count` | Integer | число внесений |
| `deposits_detail` | String(255) | время и суммы текстом: `09:12 20000; 17:03 10000` |
| `spend_rub` | Float | расход дня по всем типам |
| `left_rub` | Float | `deposits_rub − spend_rub`; плюс — остаток ушёл на ночь, около нуля — аванс выгорел |
| `last_chat_hour` | Integer, NULL | час последнего чата дня, 0–23 |
| `verdict_code` | String(16) | код для цвета, см. ниже |
| `verdict` | String(160) | вердикт словами, показывать как есть |
| `full_day` | Integer | 1 — аванс дожил до полуночи, 0 — сутки неполные |
| `balance_rub` | Float, NULL | кошелёк на момент записи; есть только у свежего дня |
| `note` | String(255), NULL | ручная пометка (авария, поздний старт открутки) |
| `loaded_at` | DateTime | когда записано |

Коды `verdict_code`:

| код | значение | цвет |
|---|---|---|
| `ok` | догорел к полуночи | зелёный |
| `burned` | выгорел в 21–22 часа | жёлтый |
| `early` | выгорел раньше 21:00, вечер не куплен | красный |
| `night` | остаток горел ночью или внесение после 22:00 | красный |
| `no_deposit` | внесений не было, жил на остатке | серый |
| `no_chats` | чатов за день нет | серый |
| `unknown` | данных не хватает | серый |

Дни с `full_day = 0` в динамике стоит помечать: провал контактов в такой день
означает кончившийся аванс, а не упавший спрос.

Настоящего остатка кошелька на полночь за прошлые дни API не отдаёт,
поэтому `left_rub` — расчётная величина, а `balance_rub` — снимок на утро.

### `chats_daily` — чаты дня

Одна строка на день и аккаунт. Ключ: (`stat_date`, `avito_id`). День чата —
по времени его создания.

| колонка | тип | смысл |
|---|---|---|
| `stat_date` | Date, PK | день (МСК) |
| `avito_id` | String(40), PK | кабинет |
| `chats` | Integer | создано чатов за день |
| `chats_evening` | Integer | из них в 19–23 |
| `chats_night` | Integer | из них в 00–07 |
| `chats_silent` | Integer, NULL | ученик открыл чат и ничего не написал |
| `chats_phone_left` | Integer, NULL | ученик оставил телефон |
| `loaded_at` | DateTime | когда записано |

`chats` — зачётная метрика плана. Это не то же самое, что «Контакты» в
`daily_stats` (там чаты плюс показы телефона), складывать их нельзя.
Цена чата = `kassa_daily.spend_rub ÷ chats_daily.chats` за те же дни.

### `inventory_daily` — состав объявлений

Снимок на утро дня. Ключ: (`snap_date`, `avito_id`). Задним числом не
восстанавливается: ряд начнётся с первого дня записи.

| колонка | тип | смысл |
|---|---|---|
| `snap_date` | Date, PK | день снимка |
| `avito_id` | String(40), PK | кабинет |
| `active` | Integer | активных объявлений |
| `on_bid` | Integer | из них на ставке |
| `new_1d` | Integer | создано за предыдущие сутки (залив доехал) |
| `expiring_7d` | Integer | срок кончается в ближайшие 7 дней |
| `price_main` | Float, NULL | преобладающая цена в карточках |
| `cl_start` | Integer | кластер «старт»: первые 0–2 суток |
| `cl_core` | Integer | «ядро»: стабильно дают контакты |
| `cl_core_expensive` | Integer | «ядро-дорогое»: дают контакты выше потолка цены |
| `cl_single` | Integer | «разовые»: один недавний контакт |
| `cl_empty` | Integer | «пустые»: просмотры набраны, контактов нет |
| `cl_untested` | Integer | «непроверенные»: просмотров мало для вердикта |
| `spend_28d_rub` | Float | расход за 28 суток |
| `spend_28d_no_contact_rub` | Float | из него на объявлениях без единого контакта за 28 суток |
| `loaded_at` | DateTime | когда записано |

Шесть кластеров в сумме дают `active`.

### `bid_batches` — партии изменений ставок

Одна строка на партию, аккаунт и день. Ключ: (`batch`, `avito_id`,
`batch_date`). Нужна как отметки на графике динамики.

| колонка | тип | смысл |
|---|---|---|
| `batch` | String(80), PK | имя партии, например `nelikvid-1103` |
| `avito_id` | String(40), PK | кабинет |
| `batch_date` | Date, PK | день применения |
| `batch_time` | String(5), NULL | время `ЧЧ:ММ`, МСК |
| `cards` | Integer | сколько объявлений затронуто |
| `n_on` | Integer | включено продвижение |
| `n_up` | Integer | ставка поднята |
| `n_down` | Integer | ставка снижена |
| `n_off` | Integer | продвижение снято |
| `n_limit` | Integer | изменён только дневной лимит |
| `reason` | String(500) | причина одной фразой |
| `loaded_at` | DateTime | когда записано |

### `plan_windows` и `plan_daily` — план/факт

`plan_windows` — шапка окна. Ключ: `window_id`.

| колонка | тип | смысл |
|---|---|---|
| `window_id` | String(40), PK | например `2500-1019-1119` |
| `title` | String(120) | подпись блока |
| `date_from` | Date | первый день окна |
| `date_to` | Date | последний день окна |
| `target_chats` | Integer | цель по чатам |
| `cpl_cap_rub` | Float | потолок цены чата |
| `avito_ids` | String(255) | кабинеты в зачёте, через запятую |
| `forecast_chats` | Integer, NULL | прогноз на конец окна, обновляется ежедневно |
| `forecast_note` | String(255), NULL | на чём стоит прогноз |
| `is_current` | Integer | 1 — окно показывать на главном экране |
| `loaded_at` | DateTime | когда записано |

`plan_daily` — плановая кривая. Ключ: (`window_id`, `stat_date`).

| колонка | тип | смысл |
|---|---|---|
| `window_id` | String(40), PK | окно |
| `stat_date` | Date, PK | день |
| `plan_chats_cum` | Float | сколько чатов должно быть набрано к концу этого дня |
| `loaded_at` | DateTime | когда записано |

Кривая не линейная: выходные в сезоне слабее будней, это уже учтено
писателем. Читатель рисует её как есть.

Факт читатель считает сам: накопленная сумма `chats_daily.chats` по
кабинетам из `avito_ids` с `date_from`. Цена чата окна — сумма
`kassa_daily.spend_rub` ÷ сумма чатов по тем же дням и кабинетам.

## Что из этого рисовать

Раскладка — на усмотрение читателя; ниже то, на какие вопросы руководителя
блоки должны отвечать.

| блок | вопрос | таблицы |
|---|---|---|
| План/факт | успеваем ли к цели и по какой цене | `plan_windows`, `plan_daily`, `chats_daily`, `kassa_daily` |
| Касса | хватило ли денег вчера, дожил ли аванс до полуночи | `kassa_daily` |
| Чаты | сколько чатов по дням и аккаунтам, цена чата | `chats_daily`, `kassa_daily` |
| Инвентарь | сколько объявлений работает, сколько пустых, что истекает | `inventory_daily` |
| Отметки партий | что меняли в день излома графика | `bid_batches` поверх «Динамики» |

Блоки должны переживать пустые таблицы: до первой записи показывать
подпись «данных пока нет», а не ошибку.

## Порядок запуска

1. Читатель заводит шесть таблиц и сообщает, что они созданы в облачной базе.
2. Писатель делает первую запись с историей и проверяет строки запросом.
3. Читатель рисует блоки по реальным данным.
4. Дальше запись идёт в утреннем ритуале AI Avitolog, тем же шагом, что и
   импорт `daily_stats`.
