# Дашборд статистики Авито

Сводит дневные выгрузки Авито по нескольким аккаунтам и введённые вручную
фактические звонки в один дашборд с удалённым доступом. Период на дашборде
выбирается календарём — от одного дня до всей истории.

## Что внутри

| Раздел | Кому | Назначение |
| --- | --- | --- |
| Дашборд | всем | Воронка, экономика, сравнение аккаунтов, география, динамика |
| Загрузка выгрузок | только вам | Приём дневных xlsx с указанием аккаунта |
| Звонки | только вам | Ввод фактических звонков по дням |
| Настройки | только вам | Названия аккаунтов, ID кабинетов, состояние базы |

Начальник заходит по ссылке со «зрительским» паролем и видит только дашборд.

## Запуск локально

```bash
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`. Без заданных паролей вход не спрашивается.

Пакетный импорт папок, минуя интерфейс:

```bash
python import_folder.py "new stats"            # подпапки названы ID кабинетов
python import_folder.py "new stats/181777530"  # одна папка, ID берётся из имени
python import_folder.py "C:/выгрузки/июль" --account 2   # в конкретный аккаунт
```

Аккаунт находится по ID кабинета Авито (имени папки); если такого ещё нет, он
создаётся как «Аккаунт 181777530» — переименуйте в настройках, привязка от этого
не потеряется.

## Как устроены данные

Все строки лежат в одной таблице `daily_stats`: строка выгрузки + день + аккаунт.
Дашборд фильтрует её по интервалу из календаря, поэтому «выгрузки за период» как
сущности нет — есть дни.

Выгрузка Авито не содержит признака аккаунта: поля «Номер объявления» и
«Название объявления» пустые, колонка «Сотрудник» есть не во всех файлах и тоже
пустая. Поэтому аккаунт задаётся папкой при пакетном импорте или выбирается
вручную при загрузке через интерфейс. Чтобы не ошибиться, форма показывает по
каждому файлу сводку — число объявлений, показы, контакты и расходы.

День берётся из имени файла (`Статистика_за_2026-07-23.xlsx`) и при
необходимости правится в форме. Повторная загрузка того же аккаунта за тот же
день **заменяет** прежние строки, а не задваивает их, — импорт папки можно
запускать сколько угодно раз. Файл за период (`Статистика_с_..._по_...`)
отклоняется: разложить его по дням нельзя.

Одно объявление даёт по строке за каждый день, поэтому «сколько объявлений» на
дашборде — это среднее за день (строки ÷ дни), а не сумма строк за период.

Звонки вводятся по дням и попадают в дашборд, если день входит в выбранный
интервал — включая крайние даты.

Расходы берутся из колонки «Расходы на объявления» = размещение + продвижение;
в проверенных выгрузках это равенство выполняется на всех строках.

## Публикация: Streamlit Community Cloud

Бесплатно, начальнику ничего ставить не нужно.

1. Создайте **приватный** репозиторий на GitHub и загрузите туда проект.
   `.gitignore` уже исключает базу, секреты и сами xlsx — коммерческие данные
   в репозиторий не попадут.
2. На [share.streamlit.io](https://share.streamlit.io) подключите репозиторий,
   главный файл — `app.py`.
3. В настройках приложения (Settings → Secrets) вставьте содержимое
   `.streamlit/secrets.toml.example`, подставив свои пароли.
4. Пришлите начальнику ссылку и «зрительский» пароль.

### Обязательно: внешняя база

Файловая система Streamlit Community Cloud **очищается при каждом перезапуске
приложения** — вместе с локальным SQLite. Без внешней базы загруженные выгрузки
и введённые звонки будут пропадать. Заведите бесплатный Postgres
([Supabase](https://supabase.com), [Neon](https://neon.tech)) и добавьте в
секреты:

```toml
db_url = "postgresql+psycopg2://пользователь:пароль@хост:5432/база?sslmode=require"
```

и в `requirements.txt` — драйвер:

```
psycopg2-binary>=2.9
```

Схема создаётся автоматически при первом запуске. Приложение больше нигде не
меняется: адрес базы читается в одном месте.

## Публикация: свой сервер

Если облако недоступно или данные не должны покидать периметр:

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # впишите пароли
docker compose up -d
```

Дашборд поднимется на порту 8501, база останется в папке `./data` и переживёт
перезапуск. Наружу выставляйте через nginx с HTTPS.

## Регулярное обновление

1. Скачали из Авито дневные выгрузки по каждому кабинету.
2. Раздел «Загрузка выгрузок» → перетащили файлы разом → отметили «Все файлы
   одного аккаунта» и выбрали его → «Импортировать».
   Локально то же самое делает `python import_folder.py "new stats"`.
3. Раздел «Звонки» → внесли фактические звонки за эти дни.

Дни докладываются как угодно: пропуски не мешают, повторы заменяются.

## Структура проекта

```
app.py                 вход, авторизация, навигация
import_folder.py       пакетный импорт папок по ID кабинетов
avito/parser.py        разбор xlsx (сопоставление по заголовкам)
avito/db.py            схема и доступ к данным
avito/metrics.py       агрегации, конверсии, звонки за интервал
avito/ui/              страницы интерфейса
```
