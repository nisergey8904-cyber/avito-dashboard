# Дашборд статистики Авито

Сводит недельные выгрузки Авито по нескольким аккаунтам и введённые вручную
фактические звонки в один дашборд с удалённым доступом.

## Что внутри

| Раздел | Кому | Назначение |
| --- | --- | --- |
| Дашборд | всем | Воронка, экономика, сравнение аккаунтов, география, динамика |
| Загрузка выгрузок | только вам | Приём xlsx с указанием аккаунта и периода |
| Звонки | только вам | Ввод фактических звонков по дням |
| Настройки | только вам | Названия аккаунтов, состояние базы |

Начальник заходит по ссылке со «зрительским» паролем и видит только дашборд.

## Запуск локально

```bash
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`. Без заданных паролей вход не спрашивается.

Разовый импорт всех файлов из папки, минуя интерфейс:

```bash
python import_folder.py "C:/Projects/stats2"
```

Соответствие «файл → аккаунт» задаётся словарём `ACCOUNT_BY_SUFFIX` в этом
скрипте: файл без скобок — первый аккаунт, `(1)` — второй и так далее.

## Как устроены данные

Выгрузка Авито не содержит признака аккаунта: поля «Номер объявления» и
«Название объявления» пустые, колонка «Сотрудник» есть не во всех файлах и тоже
пустая. Поэтому аккаунт выбирается вручную при загрузке. Чтобы не ошибиться,
форма показывает по каждому файлу сводку — число объявлений, показы, контакты и
расходы; сверьте её с тем, что ожидаете от аккаунта.

Период берётся из имени файла (`Статистика_с_2026-08-01_по_2026-08-07.xlsx`) и
при необходимости правится в форме. Повторная загрузка того же аккаунта за тот
же период **заменяет** прежние данные, а не задваивает их.

Звонки вводятся по дням. Дашборд сам относит звонок к периоду выгрузки, если
дата попадает в интервал — включая крайние дни.

Расходы берутся из колонки «Расходы на объявления» = размещение + продвижение;
в проверенных выгрузках это равенство выполняется на всех строках.

## Публикация: Streamlit Community Cloud

Бесплатно, начальнику ничего ставить не нужно.

1. Создайте **приватный** репозиторий на GitHub и загрузите туда проект.
   `.gitignore` уже исключает базу, секреты и сами xlsx — коммерческие данные
   в репозиторий не попадут.
2. На [share.streamlit.io](https://share.streamlit.io) подключите репозиторий,
   главный файл — `app.py`.
3. В настройках приложения (Settings → Secrets) вставьте содержимое
   `.streamlit/secrets.toml.example`, подставив свои пароли.
4. Пришлите начальнику ссылку и «зрительский» пароль.

### Обязательно: внешняя база

Файловая система Streamlit Community Cloud **очищается при каждом перезапуске
приложения** — вместе с локальным SQLite. Без внешней базы загруженные выгрузки
и введённые звонки будут пропадать. Заведите бесплатный Postgres
([Supabase](https://supabase.com), [Neon](https://neon.tech)) и добавьте в
секреты:

```toml
db_url = "postgresql+psycopg2://пользователь:пароль@хост:5432/база?sslmode=require"
```

и в `requirements.txt` — драйвер:

```
psycopg2-binary>=2.9
```

Схема создаётся автоматически при первом запуске. Приложение больше нигде не
меняется: адрес базы читается в одном месте.

## Публикация: свой сервер

Если облако недоступно или данные не должны покидать периметр:

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # впишите пароли
docker compose up -d
```

Дашборд поднимется на порту 8501, база останется в папке `./data` и переживёт
перезапуск. Наружу выставляйте через nginx с HTTPS.

## Регулярное обновление

1. Скачали свежие выгрузки из Авито по каждому аккаунту.
2. Раздел «Загрузка выгрузок» → перетащили все файлы разом → указали аккаунты →
   «Импортировать».
3. Раздел «Звонки» → внесли фактические звонки за дни периода.

Динамика по периодам на дашборде появится со второй загруженной неделей.

## Структура проекта

```
app.py                 вход, авторизация, навигация
import_folder.py       пакетный импорт из папки
avito/parser.py        разбор xlsx (сопоставление по заголовкам)
avito/db.py            схема и доступ к данным
avito/metrics.py       агрегации, конверсии, привязка звонков к периодам
avito/ui/              страницы интерфейса
```
